# EclipsePlayer

Cross-platform funscript-synchronized media player. C# / .NET 10, Avalonia UI 12.

**Status:** early scaffold. The solution builds but has no functionality yet.

## Target platforms

Linux desktop is the primary target (developed on CachyOS). Windows and macOS are
secondary goals. Mobile and WebAssembly are not currently targeted — the
`EclipsePlayer.Android`, `EclipsePlayer.iOS`, and `EclipsePlayer.Browser` folders are
template scaffolding and are excluded from the solution.

## Solution layout

| Project | Responsibility |
|---|---|
| `EclipsePlayer` | Avalonia UI and DI composition root |
| `EclipsePlayer.Engine` | Real-time sync orchestration (Media + Funscript + Hal) |
| `EclipsePlayer.Funscript` | Pure in-memory funscript domain model — no IO |
| `EclipsePlayer.IO` | Funscript, settings, and playlist file parsing and persistence |
| `EclipsePlayer.Hal` | Hardware abstraction layer — devices and transports |
| `EclipsePlayer.Media` | Media playback backend wrapper |

Dependency flow: `EclipsePlayer → Engine → { Funscript, IO, Hal, Media }`, and
`IO → Funscript`. The non-UI libraries target plain `net10.0` and reference no UI
framework, so the dependency direction is enforced by the compiler.

## Build

Requires the .NET 10 SDK.

```sh
dotnet build EclipsePlayer.slnx
```

`EclipsePlayer.Desktop` is the runnable head:

```sh
dotnet run --project EclipsePlayer.Desktop
```

## Background

Aims for feature parity with, and improvement on, XTPlayer and the developer's own
ScriptPlayer+ fork — reimplemented natively in C# rather than ported.

See [`ROADMAP.md`](ROADMAP.md) for the planned direction (a direction, not a
commitment — early development, expect churn).

## Development

This is a personal learning project. Application code is written by the developer,
not generated by AI. AI assistance is limited to code review, documentation, commit
messages, and project scaffolding/configuration.
